# ThinhDA — The Art of Software Engineering

Source for [thinhdanggroup.github.io](https://thinhdanggroup.github.io), a technical blog on
distributed systems, AI engineering, Python, and infrastructure.

Built with [Jekyll](https://jekyllrb.com/) and the
[Minimal Mistakes](https://github.com/mmistakes/minimal-mistakes) theme (pulled in via
`remote_theme`, not vendored), deployed by GitHub Pages from `master`.

## Local development

```bash
make install    # bundle install into vendor/bundle
make serve      # http://localhost:4000 with livereload
make build      # one-off build into _site
```

## Writing a post

Posts live in `_posts/` as `YYYY-MM-DD-slug.md`. Front matter contract:

```yaml
---
title: "Post Title"
description: "150-160 char summary. Used as the meta description — always set this."
tags:
    - Python
    - Performance
categories:
    - python
header:
    overlay_image: /assets/images/<slug>/banner.webp
    overlay_filter: 0.5
    teaser: /assets/images/<slug>/teaser.webp
toc: true
toc_sticky: true
---
```

Defaults for `layout`, `author_profile`, `read_time`, and `related` come from `_config.yml`, so
posts don't need to repeat them.

### URLs are frozen

`_config.yml` pins `permalink: /:title/`. **Do not reintroduce `:categories`** into the permalink —
every post now has a category, so that change would silently rewrite all 146 live URLs and discard
their search ranking.

### Images

Banners must be WebP and are expected in two sizes:

| File | Width | Used for |
| --- | --- | --- |
| `banner.webp` | 1600px | `overlay_image` on the post page |
| `teaser.webp` | 640px | `teaser` card on home / archive pages |

Source PNG/JPEG originals are kept alongside as archives but are **not** referenced by the site.
Regenerate derivatives with:

```bash
python script/optimize-images/to_webp.py assets/images/<slug>
```

Never reference a multi-megabyte PNG directly — banners were 115 MB total before this was enforced.

### Categories

One category per post, drawn from this fixed set:

`ai-engineering` · `databases` · `distributed-systems` · `infrastructure` · `python` ·
`software-engineering` · `web-development`

Tags are free-form but should reuse an existing tag where one fits — check `/tags/` before
inventing a new one.

## Layout

| Path | Purpose |
| --- | --- |
| `_posts/` | Published posts |
| `draft/` | Unpublished drafts (excluded from the build) |
| `_pages/` | About, archives, chatbot, and other standalone pages |
| `_layouts/` | Theme overrides: `single.html`, `posts.html` |
| `_includes/head/custom.html` | PostHog, AdSense loader, on-demand Mermaid/PlantUML |
| `_includes/footer/` | Ad units |
| `assets/images/<slug>/` | Per-post images |
| `assets/htmls/` | Standalone interactive demos embedded via iframe |
| `script/` | Publishing and maintenance tooling |

## Distribution

```bash
make indexnow       # ping IndexNow (Bing, Yandex, …)
make gsc-recent     # submit recent posts to Google Search Console
make submit-all     # both
make devto-recent N=5   # cross-post recent posts to dev.to as drafts
```

`sitemap.xml` is generated by `jekyll-sitemap` — there is no hand-maintained sitemap.

## CI

`.github/workflows/ci.yml` builds the site and runs HTMLProofer on every push and pull request,
which catches broken internal links and missing images before they reach production.
